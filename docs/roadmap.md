# What's next

These are possible upgrades once the basic pipeline feels good.

- **Mix and mux.** A stage 5 that combines the video, voiceover and music into a finished `.mp4`, with sidechain ducking so the music dips under the narration instead of sitting at a fixed level. This was deliberately left out for now; see [MUSIC_PLAN.md](MUSIC_PLAN.md).
- **A quartet LoKr.** If ACE-Step keeps sneaking non-string instruments into the cues, training a style adapter on real quartet recordings is the durable fix. Section 3 of `MUSIC GEN/instructions.md` has the procedure.
- **A native video path (tried, not workable on a 24 GB Mac).** Running MiniCPM-V 4.5 through the Python `transformers` library exposes its 3D resampler, which packs several frames into 64 tokens with real timestamps. Tested in November 2026: the full-precision weights (17.4 GB) need 19.7 GB of GPU memory on their own, above the 19.1 GB macOS allows by default. 2 of 5 clip runs ran out of GPU memory, swap reached 18 GB, and the runs that finished were slower than Ollama (199-287 s against 160-184 s, plus about 40 s to load). The published 4-bit and AWQ builds need an Nvidia GPU, and there is no MLX build of 4.5. Sending Ollama more frames instead (4 fps, up to 40) made descriptions and timing worse, not better; see `--max-frames` in [stages.md](stages.md). The 3D resampler's frame packing is what makes dense frames pay off, so this is worth another look on a Mac with 48 GB or more, or if an MLX or GGUF build gains video packing. Two things to know if you retry: transformers pre-reserves the whole model as one GPU buffer, which Metal rejects (skip `caching_allocator_warmup`), and the model code was written for transformers 4.51, older than the 5.x that Chatterbox pins, so it needs its own virtualenv.
