# Stage 4: String Quartet Scoring

Plan for wiring `MUSIC GEN/` (ACE-Step 1.5) into the video-interpreter pipeline.

**Goal:** every clip gets a classical string quartet cue that reflects what's happening in it, delivered as `<video>.music.wav` — a pre-leveled bed you drop into an editor under the voiceover. No mixing or muxing stage.

**Decisions locked:** music stem only (no mux) · fixed low gain, no ducking · preset baseline per style, LLM adjusts per clip.

---

## 1. The integration boundary

ACE-Step has its own `.venv` inside `MUSIC GEN/ACE-Step-1.5/` with its own pinned torch/MLX. The main project's `.venv` has kokoro + chatterbox-tts. **These cannot be merged** — the torch pins will fight, and you'd break working TTS to gain music.

So: talk to ACE-Step over HTTP. It ships a REST server (`acestep/api_server.py`, launched by `start_api_server_macos.sh` on port 8001).

```
pipeline.py (main venv)  ──HTTP──▶  localhost:8001  (ACE-Step venv, MLX backend)
```

Three reasons this beats shelling out to `cli.py`:

- The server holds the DiT in memory across calls. Cold-loading per clip costs 30–60s every time.
- `cli.py` is wizard/TOML-only, and pauses on `instruction.txt` when `thinking=true`. Hostile to automation.
- Clean process boundary — an ACE-Step OOM can't take down the pipeline.

**Cost:** the server has to be running. `generate_music.py` should `GET /health` first and fail with the exact launch command rather than hanging.

## 3. `generate_music.py`

New module at repo root, sibling to `generate_voice.py`. Four parts.

### 3.1 Presets — the frame

Keyed on the existing `--style` values, mirroring how `STYLES` lives in `generate_script.py`:

| style | base character | BPM range | allowed keys |
|---|---|---|---|
| `attenborough` | stately adagio, sustained legato, gentle pizzicato underneath | 58–76 | C major, G major, D major, A minor |
| `sports` | agitato, rapid spiccato, driving ostinato in the cello | 128–160 | D major, A major, E minor |
| `noir` | brooding, muted sul tasto, chromatic descending lines | 66–88 | D minor, C minor, B♭ minor |
| `reality_tv` | tense tremolo, sudden unison stabs, unresolved suspensions | 88–112 | A minor, E minor, F major |

The preset fixes tempo band, mode, and the technique vocabulary. The clip can't wander outside it.

### 3.2 LLM adjust — constrained, not freehand

Do **not** let the LLM write the caption. `MUSIC GEN/instructions.md` §4.3 is explicit: captions must not contain BPM, must not contain contradictions, and specific beats vague. A freehand LLM caption will produce "energetic string quartet with driving drums" within a week.

Instead, stage 2b asks qwen for **JSON only**, then Python assembles the caption deterministically:

```json
{
  "mood": "cautious anticipation tipping into chaos",
  "textures": ["hesitant pizzicato", "sudden accelerando"],
  "arc": "sparse and watchful, then a scrambling tutti at the pounce",
  "bpm": 72,
  "key_scale": "A minor"
}
```

System prompt constraints: pick `bpm` inside the preset's range; pick `key_scale` from the preset's allowed list; `textures` must be string-quartet playing techniques (arco, pizzicato, tremolo, sul ponticello, col legno, harmonics, double stops); never name a non-string instrument. Validate on parse — clamp BPM into range, fall back to the preset's first key if the LLM invents one, drop any texture containing a banned instrument word. Retry once on malformed JSON, then fall back to the bare preset.

### 3.3 Caption assembler

```python
caption = (
    "solo classical string quartet, two violins, viola and cello, "
    f"{preset.base_character}, {mood}, {', '.join(textures)}, "
    "chamber recording, warm close-miked acoustic, natural room decay, "
    "instrumental, no percussion, no drums, no piano, no synth, no vocals"
)
```

Character words only — BPM and key travel in the metadata fields, per §4.3 of the ACE-Step guide. The negative tail is doing real work: ACE-Step's default caption behavior drifts toward full-band arrangements.

### 3.4 ACE-Step client

`POST /release_task` → poll `POST /query_result` → download from `GET /v1/audio?path=...`.

```python
payload = {
    "prompt":          caption,
    "lyrics":          "",                       # instrumental
    "audio_duration":  max(20, ceil(video_len) + 4),
    "bpm":             bpm,
    "key_scale":       key_scale,
    "time_signature":  "4",
    "inference_steps": 8,                        # turbo
    "infer_method":    "ode",
    "batch_size":      takes,                    # 1-8, one request returns N
    "audio_format":    "wav",
    "thinking":        False,
    "use_cot_caption": False,                    # ← important
    "use_cot_language": False,
}
```

Two non-obvious settings:

- **`use_cot_caption: False`** — defaults to `True`, which lets ACE-Step's planner LM rewrite your caption. That's exactly where "and a light drum kit" gets added back. Turn it off; you hand-wrote the caption for a reason.
- **`thinking: False`** — skips the 5Hz LM entirely. Saves several GB and a lot of seconds, and you're already supplying bpm/key/duration explicitly so there's nothing for it to infer. A/B `thinking: True` in phase 3; the guide says it arranges better, but on short simple cues the gain may not pay for the memory.

Poll `status`: `0` running, `1` done, `2` failed. Poll every 2s with a hard timeout around 300s.

**Ask for longer than you need.** ACE-Step's floor is 10s and the guide notes short durations are less stable — the model rushes a musical arc into the window. Request `clip + 4s` (min 20s) and trim back.

### 3.5 Post-processing (ffmpeg)

```
trim to exact video duration → fade in 0.5s / fade out 1.5s → loudnorm
```

Since there's no mixing stage, the stem has to arrive at bed level so it sits under narration at unity gain. Measure the voiceover if it exists and target **9 LU below it**:

```bash
ffmpeg -i voiceover.wav -af ebur128=framelog=verbose -f null -   # read integrated LUFS
ffmpeg -i raw.wav -af "atrim=0:{dur},afade=t=in:d=0.5,afade=t=out:st={dur-1.5}:d=1.5,loudnorm=I={target}" music.wav
```

Default target `-25 LUFS` when there's no voiceover to measure. Expose as `--music-lufs`.

## 4. `pipeline.py` changes

New flags:

```
--score                  run stages 2b + 4
--music-out PATH         default: <video>.music.wav
--music-preset NAME      default: auto (derived from --style)
--music-takes N          default: 1; N>1 writes .music.1.wav, .music.2.wav, ...
--music-lufs FLOAT       default: auto (voiceover - 9 LU), else -25
--music-server URL       default: http://127.0.0.1:8001
--save-music-prompt      dump the assembled caption + metadata as .music.json
```

`--music-takes 3` is worth building early. ACE-Step is an iteration tool, not a one-shot — §5 of the guide is entirely about auditioning batches. One request with `batch_size: 3` is much cheaper than three requests.

Errors follow the existing convention: stage 4 returns exit code 5, and a failed stage 4 must **not** discard the voiceover you already paid for.


> **Don't use ACE-Step's own `start_api_server_macos.sh`.** It uses bash-4
> syntax (`${var^^}`) in its git-update and uv-install prompts, and macOS ships
> bash 3.2, so it fails with `bad substitution` before the server ever starts.
> Ten upstream scripts share the bug. `MUSIC GEN/start_api_server.command` does
> the same job without those two prompts, and lives outside the ACE-Step
> checkout so `git pull` there stays conflict-free.

## 7. Memory sequencing — the real risk

Your Mac mini is shared-memory. At peak this pipeline wants: minicpm-v4.5, qwen2.5:14b (~9GB), chatterbox on MPS, and the ACE-Step DiT — simultaneously, if you're careless. That's an OOM or brutal swapping.

Two mitigations, both cheap:

1. **Order stages so ollama is done before ACE-Step starts.** That's why 2b sits right after stage 2 — both use qwen, so it loads once.
2. **Explicitly release.** Pass `keep_alive=0` on the stage-2b ollama call (it's the last one), or run `ollama stop qwen2.5:14b` before stage 4. Don't rely on ollama's 5-minute idle timeout — stage 3 is faster than that.

Note the config ambiguity: `MUSIC GEN/.env` is commented for 16GB and `instructions.md` is written for 24GB. Stay on `acestep-5Hz-lm-0.6B` either way — with `thinking: False` the LM barely matters, and the 1.7B planner is a documented memory trap on shared-memory Macs.

## 8. Known risks

| Risk | Mitigation |
|---|---|
| ACE-Step adds percussion despite the caption | `use_cot_caption: False`, negative tail in the caption, audition takes. If it persists, a style LoKr trained on quartet recordings (guide §3) is the real fix. |
| Short cues sound rushed or unresolved | Generate long, trim short. Raise the pad from 4s if needed. |
| LLM emits malformed JSON | Validate + clamp, retry once, fall back to bare preset. Never let stage 2b block the pipeline. |
| Generation is slower than expected | Unknown on M4 until measured. Turbo at 8 steps should be well under a minute for 30s — **measure this in phase 1 before building anything else.** |
| Server not running | `/health` preflight with the launch command in the error. |

---

## 9. Build order

1. **Prove the loop.** Start the API server, `curl` one hand-written quartet caption at 30s, listen. Time it. This validates the whole premise before you write a line of pipeline code — and tells you whether percussion suppression actually works.
2. **`generate_music.py` standalone.** Presets, assembler, client, ffmpeg post. Runnable on its own like the other stage modules: `python generate_music.py --description d.txt --length 20 --style attenborough`.
3. **Wire into `pipeline.py`.** Flags, stage 2b, stage 4, ollama release.
4. **Tune.** A/B `thinking` on/off, tune the LUFS offset against a real voiceover, adjust preset vocabulary by ear across all six sample clips.

Phase 1 is the decision point. If ACE-Step won't hold a clean quartet texture on a hand-tuned caption, no amount of pipeline code fixes that — you'd go to LoKr training first instead.
